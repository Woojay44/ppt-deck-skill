# 场景预设

第 1 步先判定场景，再用对应预设定结构、页数和风格。用户给的要求永远优先于预设；场景不明确时在正文里问一句。

**页数和时长的通用算法**：现场讲的 PPT 约 1 分钟 1 页（标题页、致谢页约 10 秒）；讲稿按 250 字/分钟估算，数字念得慢，总时长控制在规定时长的 90% 以内。阅读型（发给别人看）不受时长限制，按内容量定页数。

## A. 学术类

| 场景 | 推荐结构 | 受众关注点 | 风格与配套 |
|---|---|---|---|
| **结题 / 毕设答辩**（大创、毕业设计） | 封面 → 背景与问题 → 目标与创新点 → 技术路线 → 关键方法（2–3 页）→ 结果（2–3 页）→ 系统或演示 → 目标完成对照表 → 成果、不足与下一步 → 分工与致谢 | 创新点、数据可靠性、与已有工作的区别、指标是否达成、局限是否如实 | 克制学术风（深蓝 + 一个强调色）；**配讲稿（Markdown）、准备清单、问答 10–16 题** |
| **开题 / 中期汇报** | 封面 → 研究背景 → 研究现状与不足 → 研究内容与目标 → 技术路线 → 进度（时间轴）→ 已有成果 / 预期成果 → 问题与计划 | 可行性、进度是否正常、风险 | 同上；中期强调“计划 vs 实际” |
| **组会汇报** | 本周 / 本阶段做了什么 → 关键结果 → 遇到的问题 → 下一步；文献分享则是：问题 → 方法 → 实验 → 我的看法 | 结果和问题，不要包装 | 信息密度可以高，阅读型为主；少装饰 |
| **学术会议报告** | 动机 → 问题定义 → 方法 → 实验 → 结论；10–15 分钟 | 方法新意和实验说服力 | 英文或中文；图多字少；可加公式页 |
| **竞赛答辩**（数模、挑战杯、创新创业赛） | 痛点 → 方案 → 核心技术 / 模型 → 结果与验证 → 应用价值 / 商业模式 → 团队 | 创新、落地价值、团队能力 | 比学术答辩更有冲击力，可以更强的视觉（大数字、对比图） |

## B. 课程与教学

| 场景 | 推荐结构 | 受众关注点 | 风格与配套 |
|---|---|---|---|
| **课程作业展示 / 小组汇报** | 选题 → 分析过程 → 结论 → 分工 | 观点清楚、分工明确 | 简洁；配讲稿 |
| **教学课件** | 学习目标 → 知识点（每个知识点：讲解 → 例子 → 小练习）→ 小结 → 作业 | 循序渐进、例子多 | 阅读型，字号可略小但 ≥ 18pt；可加动画逐条出现 |

## C. 商业与工作

| 场景 | 推荐结构 | 受众关注点 | 风格与配套 |
|---|---|---|---|
| **路演 / 融资** | 痛点 → 方案 → 市场规模 → 产品 → 商业模式 → 竞争 → 进展数据 → 团队 → 融资计划 | 市场、增长、团队 | 强视觉、大数字；10–15 页 |
| **方案汇报 / 咨询报告** | 结论先行（金字塔）：核心建议 → 分论点 + 证据 → 实施计划 → 风险 | 结论和依据 | 引擎 `modes/pyramid.md`；阅读型可以高密度 |
| **工作汇报 / 述职 / 年终总结** | 目标回顾 → 完成情况（数据）→ 亮点 → 问题与反思 → 下阶段计划 | 用数据说话 | 商务稳重风 |
| **产品发布 / 介绍** | 场景故事 → 产品亮点（一页一个）→ 演示 → 价格与上市 | 一页一个卖点 | 大图大字，引擎 `modes/showcase.md` |
| **项目复盘** | 背景 → 时间线 → 做得好的 → 问题与根因 → 改进措施 | 根因和改进 | 时间轴、鱼骨图 |
| **培训材料** | 目标 → 模块化内容 → 案例 → 练习 → 考核要点 | 可操作 | 引擎 `modes/instructional.md` |

## D. 其他

| 场景 | 说明 |
|---|---|
| **演讲 / 分享会** | 故事线（引擎 `modes/narrative.md`）；每页一句话 + 一张图 |
| **社媒图文**（小红书、朋友圈、公众号封面） | 换画布（`xiaohongshu` 1242×1660、`moments` 1080×1080、`wechat` 900×383）；字更大、留白更多；可用 AI 生图并注明 |
| **海报 / 单页** | `a4` 画布；信息分区清楚 |
| **录播 / 自动播放视频** | 引擎 `video-design` + 配音（generate-audio）；讲稿就是旁白，数字要写成念法 |

## 风格选择

- 默认：克制、清晰、高对比、投影看得清；主色一个 + 强调色一个，强调色只用于“重点 / 异常”这一种含义。
- 用户或机构有模板 / 品牌色时，以它为准（Create Template 或套用）。
- 需要更有个性的风格时，从引擎 `references/visual-styles/` 选（瑞士极简、数据新闻、编辑风、暗色科技、手绘、粉笔板等 18 种），先出样稿确认。
- 设计质量的底线规则见 `design-rules.md`，所有场景都适用。
